# Requirements: Design: drawing, importing and keeping a network

The Design group of the App and everything under it: the transactional editor, the mapped table import, the project file and the local workspace. Written on 2026-10-20 after the code (retroactive: the editor, the importer and the storage shipped in 0.02.000).

EARS (Mavin et al., RE'09, doi:10.1109/RE.2009.9). Every requirement names the gate that fails when it is violated.

| ID | Requirement | Gate |
|---|---|---|
| DS-001 | WHEN a reader draws a junction or an airway, connects two junctions or places equipment, THE editor SHALL return a new design and leave the original design unchanged. | `frontend/src/engine/editor.test.ts::draws, connects and places equipment without mutating the original design` and `frontend/src/engine/editor.test.ts::operates on deeply frozen inputs without mutating nested network values` |
| DS-002 | IF an edit transaction is invalid, THEN THE editor SHALL reject it whole and keep every existing value. | `frontend/src/engine/editor.test.ts::rejects invalid transactions and keeps existing data intact` and `frontend/src/engine/editor.test.ts::rejects contradictory fan equipment and invalid physical property edits transactionally` |
| DS-003 | WHEN an airway is split, THE editor SHALL conserve the total series resistance, place a fan only once and create no sub-minimum geometry or resistance. | `frontend/src/engine/editor.test.ts::splitting conserves total series resistance and places a fan only once` and `frontend/src/engine/editor.test.ts::does not create sub-minimum geometry or resistance during a split` |
| DS-004 | IF a junction move would make it coincident or nearly coincident with another junction, THEN THE editor SHALL refuse the move and leave the geometry unchanged, and WHEN a shared junction moves THE editor SHALL check every incident airway. | `frontend/src/engine/editor.test.ts::rejects a coincident or nearly coincident junction move without changing geometry` and `frontend/src/engine/editor.test.ts::checks every incident edge when moving a shared junction` |
| DS-005 | THE editor SHALL take identity and connectivity only from its own operations, and SHALL refuse them when a caller injects them through drawing defaults, property edits or a forged node. | `frontend/src/engine/editor.test.ts::rejects identity or connectivity injection through drawing defaults and property edits` and `frontend/src/engine/editor.test.ts::copies only coordinates when a move caller supplies a complete or forged node` and `frontend/src/engine/editor.test.ts::does not inherit forged identity or boundary properties while drawing a new junction` |
| DS-006 | IF a mapped node or airway table fails validation, even late, THEN THE importer SHALL leave the committed design and every source table unchanged. | `frontend/src/engine/tableImport.test.ts::leaves the previously committed design and all source tables unchanged after late validation failure` and `frontend/src/engine/tableImport.test.ts::rejects duplicate headings and a dangling connection before changing a design` |
| DS-007 | IF a table gives a geometry unit the importer does not know, THEN THE importer SHALL reject it and never assume metres, and THE importer SHALL convert feet and square feet explicitly. | `frontend/src/engine/tableImport.test.ts::rejects unknown geometry units instead of assuming metres` and `frontend/src/engine/tableImport.test.ts::parses quoted valid identifiers and labels, maps headers and converts feet and square feet explicitly` |
| DS-008 | THE importer SHALL measure the UTF-8 byte size, not the string length, against its limit, and SHALL cap the network rows before it allocates a design. | `frontend/src/engine/tableImport.test.ts::enforces the UTF-8 byte limit rather than JavaScript string length` and `frontend/src/engine/tableImport.test.ts::enforces network row caps before allocating an oversized design` |
| DS-009 | THE project storage SHALL allow-list the scientific fields of a project, SHALL store a baseline as inputs and recompute it on restore, and SHALL never accept forged baseline result arrays or a forged convergence claim. | `frontend/src/storage.test.ts::never accepts forged baseline result arrays or a forged convergence claim` and `frontend/src/storage.test.ts::stores baseline inputs without derived result arrays and recomputes them on device restore` and `frontend/src/storage.test.ts::allowlists scientific project fields and adds no source path or account metadata` |
| DS-010 | IF device storage is missing, blocked, malformed or invalid, THEN THE App SHALL recover a fresh workspace, and IF validation fails before a write, THEN THE old stored workspace SHALL stay. | `frontend/src/storage.test.ts::recovers a fresh workspace from missing, blocked, malformed or invalid device storage` and `frontend/src/storage.test.ts::preserves the old stored workspace when validation fails before a write` |
| DS-011 | IF a JSON import fails, THEN THE App SHALL keep the current inputs, and a project exported after an edit SHALL import to the same operating state. | `frontend/e2e/workbench.spec.ts::JSON imports preserve current inputs on failure and round-trip an edited operating state` |
