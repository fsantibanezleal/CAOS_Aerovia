# Adversarial validation: Learned screening: the two learned methods and their exports

For each requirement of [`requirements.md`](requirements.md), the check that tries to break it: what is planted or refuted, and the test that plants it. `scripts/check_sdd.py` fails when a requirement has no row here (or two), when a check is empty, and when a gate names a test that does not exist. A planted test under `tests/adversarial/` copies the files it attacks into a temporary folder, plants one defect, runs the named gate and asserts that it fails. The planted tests of `tests/adversarial/test_learned_screening_refuted.py` are written by the planted-defect unit of this release (U10a); until it lands, the guard reports the rows that name a test of that file as missing, and nothing else in this table is pending.
